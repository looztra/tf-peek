# Agent Instructions

Context for AI agents working on this repository (`tf-peek`).

## Project

- **Repository**: [looztra/tf-peek](https://github.com/looztra/tf-peek) — Terraform plan JSON to
  Markdown report with declarative, per-repository risk tiering.
- **Language**: Python, managed with `uv`. Code in `src/tf_peek/`, tests in `tests/`.
- **Main branch**: `main`.
- **Task runners**: `poe` (see `poe_tasks.toml`) and `make` (see `Makefile`, `toolbox/mk/`).
- **Docs**: user docs in `docs/`, architecture notes in `docs/architecture/`.

## Skills — read the relevant one before you work

| When you are… | Read |
| --- | --- |
| writing or editing code in `src/tf_peek/` | `.agents/skills/python-module-conventions/SKILL.md` |
| writing or editing anything under `tests/` | `.agents/skills/python-test-authoring-pytest/SKILL.md` |
| verifying a change before handing it back | `.agents/skills/python-quality-gates/SKILL.md` |
| writing commits, PR titles, PR descriptions | `.agents/skills/commit-and-pr-conventions/SKILL.md` |

Those four skills describe conventions shared by this repository template family and are kept
project-agnostic on purpose — anything specific to `tf-peek` belongs below, not in a skill.
`.agents/skills/` also carries tool skills (`uv`, `ruff`, `ty`) and workflow skills
(`commit-and-push`, `generate-pr`, `adversarial-review`). The `openspec-*` skills and
`.agents/skills/.openspec-target` are generated by the OpenSpec CLI — never hand-edit them.

## Non-negotiables

1. **Use `uv`**: run everything through `uv run …`; never invoke a bare `python`, `pytest`, or
   `ruff`.
2. **Verify before handing back**: `uv run poe style`, `uv run poe lint:all`, `uv run poe test` must
   pass (details and conditional checks: `python-quality-gates`).
3. **Conventional Commits with a mandatory scope** for commits and PR titles — CI fails a PR title
   without a scope.
4. **Explain _why_**: commit messages and PR descriptions state the reason for the change, not just
   the diff.
5. **Markdown** follows `.markdownlint.yaml`, checked by the `markdownlint-cli2` pre-commit hook.

## Repository specifics

- CLI is `typer`-based: app object `tf_peek.cli:app`; user-facing output via `typer.echo(...)`,
  diagnostics via `typer.echo(..., err=True)`, exit codes via `raise typer.Exit(code=N)`. There is no
  `logging` in `src/`; do not add `print`.
- Plan and config parsing uses `pydantic` models (`src/tf_peek/models.py`,
  `src/tf_peek/config.py`); cross-field rules go in `model_validator`.
- Report shape lives in the Jinja template `src/tf_peek/templates/report.md.j2`.
- Shared test builders are in `tests/helpers.py` (`make_plan`, `rc_entry`, `run_generate`,
  `run_generate_raw`); CLI behaviour is asserted through `typer.testing.CliRunner`.
- Everything under `tests/integration/` is auto-marked `integration` by the
  `pytest_collection_modifyitems` hook in `tests/integration/conftest.py`.
- The Markdown golden lives at
  `tests/integration/__snapshots__/test_golden/test_kitchen_sink_report.md` (syrupy). After an
  intended rendering change, regenerate with `uv run poe pytest:integration --snapshot-update` and
  review the `.md` diff like code.
- `tests/integration/test_defects.py` carries one `@pytest.mark.xfail(strict=True, ...)` per
  catalogued defect; delete the marker when the fix lands.
